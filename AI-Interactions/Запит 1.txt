// Основний промпт із функціональними вимогами // 

На базі вже готової частини веб сайту тобі необхідно реалізувати його backend частину та змінити frontend частину на основі наступних вимог та критеріїв. Сайт повинен повністю їм відповідати та максимально, на скільки це можливо, не відхилятися від них. Сайт може відповідати деяким з наступних вимог, але якщо він відповідає вимозі не повністю - то зроби так, щоб він відповідав вимозі повністю.

Сайт повинен реалізовувати наступні механізми і вимоги:

1. Модуль пошуку та автодоповнення (JS): обробка введення користувача, виведення підказок (наразі базове автодоповнення на прикладі «Так.нет»/адрес) і запуск пошуку.
2. Картографічний модуль (Leaflet + OpenStreetMap): ініціалізація карти, шари OSM, відображення маркерів/попапів і синхронізація позиції карти з результатами пошуку.
3. Модуль результатів та станів UI: список знайдених провайдерів, фільтри/деталі та керування станами (idle, loading, empty, error, results).
4. Права бічна панель на сторінці із інтерактивною картою повинна реалізовувати результат на базі пошуку провайдерів за адресою та фільтрами, що здійснюється на правій бічній панелі.
5. Сайт приймає запити пошуку провайдера за адресою, фільтрує доступних провайдерів і повертає структурований JSON. 
6. Сайт повинен мати наступну модель даних:

Для пошуку провайдера за адресою на сторінці із мапою:
City (Місто / Населений пункт)
    id: string
    name: string (назва міста, напр. "Бориспіль", "Київ")
    region: string (optional — область/район, щоб розрізняти однакові назви)
    lat: number (центр міста для карти)
    lng: number
Street (Вулиця)
    id: string
    cityId: string (посилання на City.id)
    name: string (назва вулиці, напр. "Київський Шлях")
Building / Address (Будинок та під'їзди)
    id: string
    cityId: string (посилання на City.id)
    streetId: string (посилання на Street.id)
    houseNumber: string (номер будинку, напр. "12", "45А")
    lat: number (координати будинку для позиціонування на карті)
    lng: number
    entrances: array of Entrance (optional — список під'їздів, якщо покриття відрізняється по під'їздах або треба підказувати під'їзд)
Entrance (Під'їзд)
    id: string
    buildingId: string (посилання на Building.id)
    number: string (номер або назва під'їзду, напр. "1", "2", "Під'їзд 3")
Provider (Провайдер) - Використовується для пошуку за назвою (на сторінці карти та на інших сторінках) і для сторінки провайдера:
	id: string
	name: string (напр. "Так.нет")
	slug: string (optional)
	website: string (optional)
	phone: string (optional)
	description: string (optional)
	supportedConnectionTypes: array of string (optional — загальний перелік технологій провайдера, напр. ["FTTH", "GPON"])
	maxAvailableSpeedMbps: integer (optional — верхня межа швидкості провайдера)
CoverageOffer (Покриття провайдера за адресою / під'їздом) - Описує доступність провайдера в конкретній точці та параметри, за якими працюють фільтри на карті:
    id: string
    providerId: string (посилання на Provider.id)
    cityId: string
    streetId: string
    buildingId: string
    entranceId: string (optional — null, якщо пропозиція для всього будинку)
    lat: number
    lng: number
    connectionType: string (фільтр «технологія підключення», напр. "FTTH", "GPON", "Ethernet", "Wireless")
    maxSpeedMbps: integer (фільтр «максимальна швидкість», у Мбіт/с)

7. Сайт повинен реалізовувати REST API (JSON) наступним чином для ситуацій:

7.1 Каскадне автодоповнення адреси (сторінка карти)
    GET /api/address/cities?q={text} — підказки міст за введеним текстом.
    GET /api/address/streets?cityId={id}&q={text} — підказки вулиць у межах обраного міста.
    GET /api/address/buildings?streetId={id}&q={text} — підказки номерів будинків у межах обраної вулиці.
    GET /api/address/entrances?buildingId={id}&q={text} — підказки під'їздів для обраного будинку.

Приклад відповіді (200 OK, наприклад для вулиць/будинків/під'їздів):
{
  "items": [
    {
      "id": "bldg-10",
      "label": "12",
      "lat": 50.4475,
      "lng": 30.5223
    }
  ]
}

7.2 Пошук провайдерів за назвою (автодоповнення для сторінки карти та інших сторінок)
    GET /api/providers/suggest?q={text} - Повертає збіги провайдерів за назвою для автодоповнення (на інших сторінках вибір веде на сторінку провайдера; на сторінці карти може запускати показ провайдера на мапі).
        Відповідь (200 OK):
        JSON
        {
          "providers": [
            {
              "id": "prov-taknet",
              "name": "Так.нет",
              "connectionTypes": ["FTTH", "GPON"],
              "maxSpeedMbps": 1000
            }
          ]
        }

7.3 Пошук провайдерів для відображення на карті (за адресою або назвою провайдера + фільтри)
    GET /api/map/providers
        Query-параметри:
            Режим адреси: cityId, streetId, buildingId, entranceId (optional)
            Або режим назви: providerName або providerId
            Фільтри: connectionType (optional), minMaxSpeedMbps (optional)
        Відповідь (200 OK):
	{
  "center": {
    "lat": 50.4475,
    "lng": 30.5223
  },
  "items": [
    {
      "coverageId": "cov-1",
      "providerId": "prov-taknet",
      "providerName": "Так.нет",
      "lat": 50.4480,
      "lng": 30.5231,
      "connectionType": "FTTH",
      "maxSpeedMbps": 1000
    }
  ]
}

7.4 Детальна інформація про провайдера (сторінка провайдера)
    GET /api/providers/{providerId} - Повертає дані провайдера для сторінки інформації про нього (200 OK / 404 Not Found):
{
  "id": "prov-taknet",
  "name": "Так.нет",
  "description": "Оператор широкосмугового доступу до мережі Інтернет.",
  "website": "https://example.ua",
  "phone": "+380000000000",
  "connectionTypes": ["FTTH", "GPON"],
  "maxSpeedMbps": 1000
}

Після реалізації вкажи виконані зміни, що додано чи прибрано, як воно має взаємодіяти між собою. Якщо не достатньо інформації для виконання дій - спочатку уточни те, що необхідно для якісного виконання завдання і вже потім виконуй його. Не вигадуй нічого зайвого самостійно. Для реалізації бекенду використовувати Node.js, а база даних реалізується на базі простого JSON файлу.
