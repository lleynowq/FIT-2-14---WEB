Попрацював 11m 30s

Реалізацію завершено. На базі попередньої версії ISPCheck створено повноцінну демонстраційну систему з Node.js backend, REST API та JSON-базою даних. Дизайн трьох сторінок збережено, а функціональність пошуку й карти розширено.

1. Що було реалізовано
Backend на Node.js

Сервер створено на вбудованому модулі http, без додаткових залежностей. Він обробляє запити, читає JSON-базу, виконує пошук, фільтрацію та повертає структуровані JSON-відповіді.

База даних JSON

Створено файл data/db.json, який містить шість основних масивів даних:
Сутність	Призначення
cities	Міста
streets	Вулиці
buildings	Будинки та координати
entrances	Під'їзди
providers	Інтернет-провайдери
coverageOffers	Покриття та характеристики послуг

До CoverageOffer додано погоджене поле energyIndependent.

REST API

Реалізовано всі чотири групи маршрутів із завдання:
Метод	Endpoint	Призначення
GET	/api/address/cities	Пошук міст
GET	/api/address/streets	Пошук вулиць
GET	/api/address/buildings	Пошук будинків
GET	/api/address/entrances	Пошук під'їздів
GET	/api/providers/suggest	Автодоповнення провайдерів
GET	/api/map/providers	Пошук доступних пропозицій і фільтрація
GET	/api/providers/:providerId	Детальна інформація про провайдера

Додатково створено /api/meta/filters для динамічного формування списків технологій і швидкостей у фільтрах.
2. Зміни frontend










Інтерактивна карта

Додано маркери за результатами API, інформаційні popup-вікна, перехід до сторінки провайдера та автоматичне центрування карти за результатами пошуку.













Каскадне автодоповнення адреси

Користувач послідовно обирає місто, вулицю, будинок та під'їзд. Зміна попереднього поля скидає залежні поля.













Права бічна панель

У ній тепер розміщені адресний пошук, фільтри технології, швидкості та енергонезалежності, а також список знайдених провайдерів і доступних адрес.



Панель результатів підтримує п'ять станів:
- idle — очікування запиту;
- loading — завантаження;
- empty — результатів не знайдено;
- error — сталася помилка;
- results — знайдено пропозиції.
Пошук за назвою провайдера теж переведено на API. На головній сторінці та сторінці провайдера вибір відкриває його профіль, а на сторінці карти — показує його пропозиції на карті.

Демонстраційні дані
Важливо розрізняти реальні адреси та тестові параметри: доступність «Так.нет», технології GPON/FTTH, швидкості 300–1000 Мбіт/с та енергонезалежність створені для тестування функціоналу. Це не підтверджені відомості про фактичну мережу оператора.

Інші чотири назви провайдерів із макета прибрано. Водночас модель дозволяє додавати нових провайдерів через JSON без переписування пошукового механізму.

5. Як запустити оновлений сайт
Тепер Live Server використовувати не потрібно. Замість нього запускається Node.js сервер, який обслуговує і frontend, і backend.
1. Завантаж ZIP-архів та розпакуй його.
2. Переконайся, що встановлений Node.js версії 18 або новішої.
3. Відкрий папку ISPCheck у Visual Studio Code.
4. Відкрий термінал і виконай:
npm start


5. У браузері відкрий:
http://localhost:3000/


Для зупинки сервера натисни Ctrl + C у терміналі.

npm install виконувати не потрібно — бекенд не має сторонніх npm-залежностей. Для карти, як і раніше, необхідне інтернет-з'єднання.
6. Що перевірено та що залишилося
HTTP-перевірки пройдено
Перевірив синтаксис JavaScript, коректність JSON, HTML-структуру та HTTP-відповіді всіх реалізованих API-маршрутів. Перевірено також реакцію на невідомого провайдера (404) і некоректний ланцюжок адресних ID (400).

Поки що не реалізовані: надсилання відгуків, авторизація, кабінет оператора та повідомлення про помилки. Їхні кнопки залишені як елементи інтерфейсу без функціональності.

Синя зона Русанівки також поки залишається приблизним полігоном із попередньої версії. Адресні результати API відображаються окремими маркерами; повноцінні геометричні межі покриття для кожного провайдера потребуватимуть окремої моделі геоданих.

Головне архітектурне досягнення: тепер ISPCheck не прив'язаний до одного провайдера. Нові міста, адреси та оператори можна додавати в data/db.json, а пошук, автодоповнення, фільтри та API використовуватимуть ці записи автоматично.
