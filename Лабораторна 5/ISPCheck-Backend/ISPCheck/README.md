# ISPCheck — frontend + Node.js REST API

Навчальний демонстраційний сайт для пошуку інтернет-провайдерів за назвою та адресою. Проєкт зберігає попередній візуальний стиль ISPCheck, але пошук, карта та сторінка провайдера тепер отримують дані з Node.js API.

> **Важливо про дані:** це демонстраційна база. Факт наявності «Так.нет» у наведених будинках, швидкість, технологія та енергонезалежність не підтверджені провайдером і не повинні сприйматися як комерційна пропозиція.

## 1. Запуск

Потрібен Node.js версії 18 або новішої. Сторонні npm-пакети для бекенду не потрібні: сервер використовує вбудовані модулі Node.js.

```bash
npm start
```

Після запуску відкрийте:

- `http://localhost:3000/` — головна сторінка;
- `http://localhost:3000/map.html` — інтерактивна мапа;
- `http://localhost:3000/isp-info.html?id=prov-taknet` — сторінка провайдера.

Для розробки з автоматичним перезапуском сервера:

```bash
npm run dev
```

Не запускайте нову версію через Live Server: тепер сторінки мають звертатися до Node.js API на тому самому origin. Саме команда `npm start` запускає і сайт, і API.

Порт за замовчуванням — `3000`. Його можна змінити через змінну середовища `PORT`.

## 3. REST API

Усі відповіді API мають формат JSON. Пошук не змінює JSON-файл: сервер читає дані з `data/db.json` та повертає відфільтровані результати.

### Каскадне автодоповнення адреси

- `GET /api/address/cities?q=Ки` — пошук міст.
- `GET /api/address/streets?cityId=city-kyiv&q=Енту` — вулиці обраного міста.
- `GET /api/address/buildings?streetId=street-entuziastiv&q=21` — будинки обраної вулиці.
- `GET /api/address/entrances?buildingId=building-entuziastiv-21&q=1` — під'їзди вибраного будинку.

Перші три рівні зв'язуються через `cityId`, `streetId` та `buildingId`. Якщо користувач змінює попередній рівень адреси, frontend скидає вибрані нижчі рівні, щоб не сформувати суперечливу адресу.

### Пошук провайдера за назвою

`GET /api/providers/suggest?q=так`

Повертає масив `providers` з `id`, `name`, `connectionTypes` та `maxSpeedMbps`. Порожній `q` повертає весь список провайдерів — це дозволяє динамічно отримувати їх перелік із JSON-бази.

### Пошук пропозицій на мапі

`GET /api/map/providers`

Підтримуються два режими — адресний або за провайдером. В одному запиті потрібно передавати лише один режим:

```text
/api/map/providers?cityId=city-kyiv&streetId=street-entuziastiv&buildingId=building-entuziastiv-21
/api/map/providers?providerId=prov-taknet
/api/map/providers?cityId=city-kyiv&connectionType=GPON&minMaxSpeedMbps=500&energyIndependent=true
```

Фільтри:

- `connectionType` — точне значення технології;
- `minMaxSpeedMbps` — мінімальна потрібна швидкість, сервер залишає пропозиції зі швидкістю не нижче вказаної;
- `energyIndependent=true` — залишає лише енергонезалежні пропозиції.

Якщо переданий `entranceId`, враховуються пропозиції для цього під'їзду та пропозиції з `entranceId: null`, які діють для всього будинку. Перевіряється належність ID до одного ланцюжка адреси.

Відповідь містить `center` і `items`. Кожен елемент включає ID покриття, провайдера, адресу, координати, технологію, швидкість та ознаку енергонезалежності. Frontend додає маркери, попапи та синхронізує позицію й масштаб карти з результатами.

### Деталі провайдера

`GET /api/providers/prov-taknet`

Повертає дані провайдера: `id`, `name`, `description`, `website`, `phone`, `connectionTypes`, `maxSpeedMbps`. Не заповнені необов'язкові поля повертаються як `null`.

### Метадані фільтрів

`GET /api/meta/filters`

Додатковий службовий endpoint frontend використовує для побудови фільтрів із наявних даних JSON: технології, значення швидкості та наявність записів з енергонезалежністю. Це дозволяє додавати нові технології та швидкості в JSON без редагування HTML.

## 4. Модель JSON-бази

Файл `data/db.json` містить масиви:

- `cities` — міста з центрами карти;
- `streets` — вулиці, пов'язані з містом через `cityId`;
- `buildings` — будинки з `cityId`, `streetId`, номером і координатами;
- `entrances` — під'їзди, пов'язані з `buildingId`;
- `providers` — провайдери та їхні загальні можливості;
- `coverageOffers` — пропозиції покриття за адресою з технологією, швидкістю та `energyIndependent`.

Щоб додати іншого провайдера, потрібно додати його до масиву `providers` і створити відповідні записи в `coverageOffers`. Підказки, API та список результатів автоматично працюватимуть з усіма провайдерами з бази. Для нового міста, вулиці чи будинку спочатку додаються відповідні батьківські записи, а потім пов'язані з ними сутності.

## 6. Стани інтерфейсу

Права панель результатів використовує стани:

- `idle` — очікування введення адреси або вибору провайдера;
- `loading` — виконується API-запит;
- `results` — знайдені пропозиції, відображені у списку й на мапі;
- `empty` — запит успішний, але збігів немає;
- `error` — сервер або запит повернув помилку.

Фільтри повторно запускають останній пошуковий запит. Якщо пошук був за адресою, зберігаються ID адреси; якщо за провайдером — ID провайдера.

## 7. Межі поточної реалізації

- Синя область на карті лишається орієнтовним візуальним полігоном із попереднього прототипу. Адресні результати показуються окремими маркерами з координатами з JSON.
- Демонстраційна JSON-база не є реальною базою «Так.нет».
- Відгуки, кабінет, повідомлення про помилку та кабінет оператора поки не підключені до backend.
- JSON-файл підходить для навчального/демонстраційного проєкту з невеликим обсягом даних. Для багатокористувацької продуктивної системи з одночасним редагуванням варто буде перейти на повноцінну СУБД.
- Карта потребує інтернет-з'єднання для завантаження Leaflet із CDN та картографічних плиток OpenStreetMap.
